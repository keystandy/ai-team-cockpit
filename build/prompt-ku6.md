## 老板已裁决的一条（覆盖 SPEC，按这个做）

SPEC 第 1 节写「只有指定验收人本人可通过或退回」。但页面上只有一个操作者（老板），没有登录身份，照那条实现会点不动。

改为：**老板可代指定验收人执行验收**。

- 按钮文案：「以{验收人}身份通过」「以{验收人}身份退回」
- 验收记录里记为「{验收人}（老板代验收）· {时间}」
- **负责人自验仍然禁止**：负责人是 AI 成员，永远不会是操作者，所以这条天然成立，不用额外判断
- 其余规则不变：验收人 ≠ 负责人、证据不能为空、只有已验收才进成果区

## 核心逻辑要求

1. **状态五态**：`等待中 / 进行中 / 待验收 / 已验收 / 失败`。原来的「已完成」删掉。
2. **交活只到待验收**：子任务跑完 → 状态变 `待验收`，**绝不自动变已验收**。原来那种跑完就标完成的路径必须改掉。
3. **每单自动分配验收人**：交活时从其他成员里选（排除负责人，优先在线），显示在单上。没有其他人可选时，状态停在待验收并提示「暂无可选验收人」。
4. **证据**：交活时生成一条证据。因为这是演示页，证据必须是**演示证据**，格式如 `演示证据：{任务名} 的执行输出摘要（第 1-12 行）`，并在证据块标「演示」。不许伪造真实文件路径。
5. **证据为空不能通过**：通过按钮禁用 + 提示文案照 SPEC 第 6 节。
6. **退回**：内联输入框，理由必填，确认后任务回 `等待中`，记录退回人/时间/理由，失败与退回历史都保留。
7. **成果区联动**：只有 `已验收` 才创建成果条目（演示成果同样要过闸门，保留 `◇ 演示` 标签）。待验收的不要提前进成果区。
8. **事件流**：交活、待验收、验收通过、退回四类事件，文案照 SPEC 第 5 节固定格式。

## 自测（做完自己跑，写进报告）

1. 发布一次任务，四张派活单跑完后状态是 `待验收`，**不是** `已验收`
2. 每张单上能看到：负责人、验收人（≠负责人）、验收条件、证据（带「演示」标记）
3. 点「以{验收人}身份通过」→ 状态变 `已验收`，事件流出现验收通过记录，成果区新增一条
4. 另选一单点退回 → 出现理由输入框，不填理由时「确认退回」禁用；填了确认后任务回 `等待中`，事件流出现退回记录
5. 待验收的单不进成果区
6. 1440×900 与 1280×800 下派活单可变高，不溢出、不遮挡
