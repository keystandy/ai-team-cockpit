# P0 验收门设计规格：待验收 → 已验收

> 范围：派活单、流程节点、实时事件、团队成果区。只定义视觉与交互，不定义实现。
> 术语统一用「交活、验收、退回、负责人、验收人」；原「交结果」入口改称「交活」，原「已完成」状态不再出现。

## 1. 五态与验收门

- 状态仅为 **等待中 → 进行中 → 待验收 → 已验收**，任一分支可进入 **失败**；失败沿用现有重试、改派规则。
- 负责人点「交活」后只能进入待验收；执行动画结束、命令退出或结果生成都不能自动改为已验收。
- 每张派活单必须有验收人，且验收人 ≠ 负责人；只有指定验收人本人可通过或退回，其他人只读。
- 通过必须同时满足：当前为待验收、验收人在线、证据非空。退回必须填写一行理由，退回给原负责人并回到等待中。
- 待验收时锁定验收条件与证据，避免验收依据中途变化；退回后负责人可修订证据，再交活形成新一轮验收。
- 每轮交活、通过、退回均追加历史，不覆盖旧记录；已有失败历史永久保留，已验收后不再显示操作按钮。

## 2. 派活单信息结构与文字版式

- 卡片沿用 `--bg-card`、`--border-strong`、`--radius-md`，内边距 `16px`；字段间距 `12px`，分组间距 `16px`，分隔线 `--border-subtle`。
- 字段标签统一 **T4 / `--text-secondary`**；字段值统一 **T3 / `--text-primary`**；时间统一 **T4 / `--text-secondary`**。
- 任务名为 **T3 加粗 600 / `--text-primary`**；状态标签固定右上角，名称与标签间距 `8px`，长任务名换行而不挤压状态。
- 负责人、验收人上下排列在任务名下方；验收人同时显示在线标记。不能只用头像或颜色表明身份。
- 验收条件紧随验收人，使用只读信息块；命令保留在原命令位；证据位于命令之后、操作区之前，让验收人按「条件 → 命令 → 证据」核对。
- 验收条件、命令、证据均用 `--bg-subtle`、`--radius-sm`、内边距 `12px`，值用 **T3 / `--text-primary`**；长路径和摘要自然换行，不横向撑破卡片。
- 证据文件路径保留完整路径与可选行号，如 `src/a.ts:20-36`；输出摘要保留原文。可查看时用 **T3 / `--primary`** 文字链接「查看证据」，不只用图标。
- 有退回时，在证据下方显示「退回理由」：标签 **T4 / `--status-failed`**，理由 **T3 / `--text-primary`**，退回人与时间用 **T4 / `--text-secondary`**；多轮按时间倒序。
- 已验收时显示「验收记录」，含验收人、验收时间、当轮证据；有失败时，在最下方保留「失败历史」，原因用 **T3 / `--status-failed`**，时间用 **T4 / `--text-secondary`**。

```text
┌ 派活单 ────────────────────────┐
│ {任务名}              {图形 状态} │
│ 负责人：{负责人}                  │
│ 验收人：{验收人} · {成员状态}      │
│ 验收条件                         │
│ {可核对的交付标准}                │
│ 命令                             │
│ {原有命令内容}                    │
│ 证据                             │
│ {文件路径:行号 或 输出摘要}        │
│ [查看证据]                       │
│ 退回理由（有退回时）              │
│ {理由}                           │
│ {验收人}退回给{负责人} · {时间}    │
│ 验收记录（已验收时）              │
│ {验收人} · {验收时间} · {当轮证据} │
│ 失败历史（有失败时）              │
│ {失败原因} · {时间}               │
│ ──────────────────────────── │
│ {退回理由内联输入区，按需出现}     │
│ [退回]                    [通过] │
└────────────────────────────────┘
```

## 3. 五态视觉与出现位置

| 状态 | 固定图形与文字 | 文字／图形颜色 | 卡片状态位与流程节点 | 实时事件 | 团队成果区 |
|---|---|---|---|---|---|
| 等待中 | `○ 等待中` | `--text-secondary` | 派活单右上；负责人当前子任务位 | 创建、退回事件带 `○` | 不出现 |
| 进行中 | `▶ 进行中` | `--primary` | 派活单右上；当前执行成员卡与选中链路 | 接活、进度事件带 `▶` | 不出现 |
| 待验收 | `□ 待验收` | `--status-busy` | 派活单右上；负责人卡显示该状态，执行连线恢复浅灰 | 交活、待验收事件带 `□` | 不出现，连灰态占位也不放 |
| 已验收 | `✓ 已验收` | `--status-online` | 派活单右上；负责人卡显示该状态，连线浅灰 | 验收通过事件带 `✓` | 唯一可出现的任务状态，标签放成果卡右上 |
| 失败 | `× 失败` | `--status-failed` | 派活单右上；失败成员卡及最后一段连线 | 失败事件带 `×` | 不出现 |

- 状态标签统一 **T4**、图形 `12px × 12px`、图形与文字间距 `4px`；底色 `--bg-subtle`、圆角 `--radius-sm`、内边距纵向 `4px`／横向 `8px`。
- 所有状态必须同时有图形和文字；不得仅改变圆点颜色。成员在线／忙碌／离线仍按成员状态规范，不与任务五态混用。

## 4. 验收操作区

- 仅待验收显示操作区，位于证据之后；顶部用 `1px --border-subtle` 分隔，上间距 `16px`，按钮高 `32px`、**T3**、`--radius-md`，按钮间距 `16px`。
- 「退回」在左：白底、`--border-strong` 描边、`--status-failed` 文字，hover 用 `--bg-subtle`；「通过」在右：`--primary` 底、白字，hover 用 `--primary-hover`。
- 禁用态统一 `--bg-subtle` 底、`--text-placeholder` 字、`--border-strong` 描边，不用整卡透明度；按钮下方以 **T4 / `--text-secondary`** 直接说明原因。
- 当前用户是负责人时，通过、退回均禁用，固定提示「负责人不能验收自己的活，请由指定验收人处理。」入口不隐藏。
- 非负责人但也不是指定验收人时，两钮禁用，提示「只有指定验收人可以通过或退回。」证据为空或验收人离线时也禁用，文案见第 6 节。
- **退回理由用内联展开，不用浮层**：理由、验收条件和证据必须在同一屏保持上下文，且避免浮层遮挡与额外确认层级。
- 点「退回」后，在按钮上方出现单行输入框：高 `32px`、**T3**、白底、`--border-strong`、`--radius-md`、内边距 `12px`；占位 **T4 / `--text-placeholder`**：「写一句退回理由（必填）」。
- 输入框下为「取消」文字按钮与「确认退回」描边按钮；理由为空或仅空格时确认禁用，并显示 **T4 / `--status-failed`**：「退回理由不能为空。」编辑期间「通过」禁用，取消则恢复原操作区。
- 内联区出现只用一次 `160ms` 淡入与 `translateY(-4px) → 0`，不过渡高度，不推动其他卡片做布局动画。

## 5. 实时事件新增固定文案

| 事件 | 固定文案 |
|---|---|
| 交活 | `{负责人}交活：「{任务名}」` |
| 待验收 | `「{任务名}」待验收，验收人：{验收人}` |
| 验收通过 | `{验收人}验收通过：「{任务名}」；证据：{证据路径或摘要}` |
| 退回 | `{验收人}退回「{任务名}」给{负责人}：{退回理由}` |

- 时间在前、事件在后，新事件顶部插入并单次 `160ms` 淡入；退回事件中的负责人就是接回任务的人，不省略。

## 6. 空态与异常

- **没有验收人可选**：候选列表排除负责人，离线成员不可新选；下拉禁用并显示「暂无可选验收人」。新单不能确认派发，存量单不能交活或通过。
- 无验收人提示用 **T4 / `--status-failed`**：「暂无其他在线成员可验收，请等待成员上线或改派负责人；负责人不能验收自己的活。」不自动指定负责人或老板兜底。
- **验收人离线**：已选验收人保留并显示 `○ 离线`；通过、退回禁用，提示「验收人离线，暂不能验收；可等待上线或改选在线验收人。」不得代验或自动通过。
- **证据为空**：证据块显示 **T4 / `--text-placeholder`**「未提供证据」，通过禁用；待验收时提示 **T4 / `--status-failed`**：「证据为空，不能通过；请退回负责人补充文件路径（可带行号）或输出摘要。」
- 空白字符不计为证据；退回后负责人补充证据，再交活，验收人不能替负责人伪造证据。

## 7. 团队成果区联动

- 只有已验收才创建成果条目；待验收与失败不进入，演示成果也必须经过同一验收人、证据和验收门，并保留「演示」标签。
- 通过瞬间，派活单状态由 `□ 待验收` 切为 `✓ 已验收`，颜色与描边用 `120ms` 过渡；操作区原位替换为只读验收记录，不弹窗。
- 成果条目在成果区顶部首次出现，而非把原有待验收卡搬入；单次 `160ms` 淡入，不自动滚动、不闪烁、不撒花，其他卡片不做位移动画。
- 成果卡必须显示任务名、负责人、验收人、验收时间、证据及 `✓ 已验收`；任务名 **T3 加粗 600**，人员与时间 **T4 / `--text-secondary`**，证据 **T3 / `--text-primary`**。
- 实时事件同步追加验收通过记录；流程连线恢复 `--border-subtle`，不保留蓝色执行链路。

## 8. 变量与最终检查

- **不新增任何变量**；全部颜色、T1–T5、间距、4／8／999 圆角及动效均复用 `build/SPEC.md`。禁止阴影堆叠、发光、渐变和无限循环动画。
- 只看派活单即可回答：负责人是谁、指定验收人是谁、验收条件与当轮证据是什么、由谁因何理由退给了哪位负责人。
