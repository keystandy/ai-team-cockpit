# 团队成果区 · 设计规格（SPEC-ARTIFACTS）

> 只规定「团队成果区」。视觉与交互基准沿用 `build/SPEC.md`，术语沿用 `build/strings.md`；未列出的装饰一律不做。

## 1. 位置与定位

- 在主区、四张员工卡（小深／小酷／小克／小豆）**正下方**，与员工卡组间距 `--space-4`（20px），占满主区宽度；右栏三段不动。
- 主区顺序固定：老板输入卡 → 小棒协调卡 → 员工卡组 → **团队成果区**。
- 它回答「这轮团队到底交付了什么」，是验收入口，不是第二个实时事件流；事件讲过程，成果只列可打开的结果。

## 2. 整体版式

一张白底卡片：`--bg-card` + `1px solid --border-strong` + `--radius-md`，内边距 `--space-3`（16px）。标题栏一行，下方**一行一条成果**，不做多列网格：名称与来源长短不一，单列两行式扫读最快，窄屏也不用横向挤压。

```
┌────────────────────────────────────────────────────────────────────┐
│ 团队成果  真实 5 · 演示 2                              全部｜真实｜演示 │
├────────────────────────────────────────────────────────────────────┤
│ AI 协作工作台 · 设计规格书  [✓ 本机文件]              查看  复制路径  │
│ (头像)小克 · 本轮实作 / 撰写设计规格 · 2026-11-14 12:20  `build/SPEC.md` │
├────────────────────────────────────────────────────────────────────┤
│ 客服问答整理  [◇ 演示]                                查看  复制路径  │
│ (头像)小豆 · 派活单「整理客服问答」/ 子任务「归类」 · 14:32            │
└────────────────────────────────────────────────────────────────────┘
```

- 标题栏：左侧 T2「团队成果」+ T4 计数「真实 n · 演示 n」；右侧筛选「全部｜真实｜演示」，当前项 `--primary-soft` 底 + `--primary` 字，其余 `--text-secondary`，切换 160ms。
- 每条成果两行：上为名称行（名称 + 标签 + 操作），下为元信息行（产出人、来源、时间、路径）。行纵向内边距 `--space-2`（12px），行间 `1px solid --border-subtle`，首尾不多加分隔线。
- 操作固定在名称行右侧，按钮高 32px，间距 `--space-2`；不得只在 hover 出现。

## 3. 每条成果的信息层级

| 层级 | 内容 | 字号 | 颜色与样式 |
|---|---|---|---|
| 主要 | 成果名称 | T3（14/600/22） | `--text-primary`，最多两行，超出省略并给完整 `title` |
| 主要 | 真实／演示标签 | T4 | 见第 4 节，紧跟名称右侧 `--space-2` |
| 次要 | 产出人头像 + 名字 | T4 | 头像 20px、`--radius-round`，与名字间距 `--space-1`；名字 `--text-secondary` |
| 次要 | 来源（派活单 / 子任务 / 本轮实作） | T4 | `--text-secondary`，与名字、时间用「·」分隔 |
| 次要 | 完成时间 | T4 | `--text-secondary`，`YYYY-MM-DD HH:mm`，数字 `tabular-nums` |
| 次要 | 本机路径代码片 | T4 | `--bg-subtle` 底 + `--radius-sm`，内边距 4px 8px，`--text-secondary`，仅真实条目显示 |
| 操作 | 查看 | T3 | 文字按钮 `--primary`，hover `--primary-hover` |
| 操作 | 复制路径 | T3 | 次按钮白底 + `--border-strong`，hover `--bg-subtle` |

名称是唯一重色重字，其余一律次要；不用大数字、不用图标堆砌文件类型。

## 4. 真实与演示的区分（同一标签槽位，不靠颜色单独表意）

| 类型 | 标签文字与图形 | 文字色 | 底色 | 位置 | 路径与操作 |
|---|---|---|---|---|---|
| 真实 | `✓ 本机文件` | `--status-online` | 成功浅底 `#F0FDF4`（SPEC 已列） | 名称右侧 `--space-2`，`--radius-sm`，内边距 4px 8px | 显示真实路径代码片；查看、复制路径均可用 |
| 演示 | `◇ 演示` | `--text-secondary` | `--bg-subtle` | 同上，同尺寸同位置 | **不显示路径**；复制路径置灰禁用，旁注 T4「演示成果，未生成本机文件」 |

- 不用大红警告条、不整卡铺色、不给演示行降透明度；演示条目正文仍 `--text-primary`，可读性一致，只靠标签与路径有无区分。
- 演示「查看」打开摘要浮层，浮层标题旁同样挂 `◇ 演示`，正文首行 T4 写明「这是演示流程生成的内容，不是本机文件」。
- 标题栏计数与筛选始终分列真实／演示，任何视图都不把两者合并成一个数字。

## 5. 数据来源与字段

- **真实（种子数据，路径真实存在）**：完成时间取文件实际修改时间；来源写「本轮实作 / 具体子任务」，**不伪造派活单编号**，不挂在演示派活单名下。

| 成果名称 | 产出人 | 路径 | 来源 |
|---|---|---|---|
| AI 协作工作台 · 设计规格书 | 小克 | `build/SPEC.md` | 本轮实作 / 撰写设计规格 |
| 术语与文案表 | 小豆 | `build/strings.md` | 本轮实作 / 统一术语与文案 |
| 工作台实现 | 小酷 | `index.html` | 本轮实作 / 页面实现 |
| 工具体验报告 | 小酷 | `build/REPORT-ku2.md` | 本轮实作 / 工具体验复盘 |
| 使用说明 | 小棒 | `README.md` | 本轮实作 / 撰写使用说明 |

- **演示**：派活单全部子任务「已完成」后自动追加一条；来源填该演示派活单名 + 子任务名，完成时间取派活单完成时间，标签固定 `◇ 演示`，字段结构真实一致，便于以后接真数据。
- 复制路径复制基于项目根的绝对路径；文件读取失败时该条标 `× 文件读取失败`（`--status-failed`），保留路径与重试入口，不静默消失。

## 6. 状态与空态

- **空态（一条都没有）**：上下留白 `--space-7`（40px），T3「成果会出现在这里。」+ T4「小棒派活、成员交结果后，这里会列出能打开的文件。」，说明用 `--text-placeholder`，无插画、不写「暂无数据」。
- **筛选后为空**：T4「这一类还没有成果。」，保留标题栏与筛选，不清空整块。
- **加载中**：列表区显示一行静态 T4「正在读取本机成果…」，`--text-secondary`；禁止旋转图标与骨架屏闪烁。
- **生成中**：派活单进行中时，列表顶部插一行静态 `◐ 进行中`（`--status-busy`）+ T4「小酷正在生成「工作台实现」…」，无操作按钮；完成后 200ms 内容替换为正式条目，禁止无限循环动画。
- **加载失败**：T4「成果没读出来，请点刷新重试。」+ 文字按钮「重试」。

## 7. 多条（8 条以上）

- **排序**：真实在前、演示在后，各自按完成时间倒序，最新在最上；老板先看到可验收的真文件。
- **可视窗口 6 条 + 列表内部纵向滚动**，卡片高度不随条数撑开页面；滚动只发生在列表内，不抢页面滚动位置。
- **容量上限 50 条**：超出后最旧的演示条目先收起，列表末尾一行 T4「更早的 n 项成果已收起」；真实条目不自动删除。
- **为什么滚动而不分组**：成果是按时间验收的清单，分组标题在空组时制造噪音、多占两行高度，还会打断「从上往下扫一遍」；单一清单 + 固定标签槽位 + 筛选已足够区分两类，滚动让首屏始终留得住输入框与员工卡。

## 8. 交互、响应式与动效

- 「查看」开浮层：`--bg-overlay` + `--border-strong` + `--radius-md`，无阴影；标题 T2 + 路径 T4，正文只读、内部滚动，Esc 关闭并还焦。
- 「复制路径」成功后按钮文字一次性变为「已复制」，200ms 过渡，2s 后还原，不弹窗、不循环闪烁。
- 新成果插入一次 160ms 淡入；列表容器 `aria-live="polite"`；按钮可 Tab 到达，`aria-label` 为「查看{成果名}」「复制{成果名}路径」；焦点环沿用 SPEC。
- `≥1200px` 按上图两行式；`768–1199px` 保持两行式，来源可换行；`<768px` 操作移到元信息行下方左对齐，名称与路径允许换行，不出现横向滚动。
- 过渡只用 120／160／200ms ease-out，仅 `color、background-color、border-color、opacity` 与浮层 `translateY(-4px)→0`；`prefers-reduced-motion` 时归 0ms。

## 9. 新增变量

**无。** 全部颜色、字号、圆角、间距、控件高度均取自 `build/SPEC.md` 第 2–6 节；标签浅底仅使用 SPEC 已列的 `#F0FDF4`，未引入第六级字号、第四种圆角或刻度外间距。

## 10. 验收标准

老板不看右栏、不点任何按钮，扫一眼本区就能说出：这轮交付了哪几个文件、分别谁做的、来自哪张派活单或哪项实作、什么时候完成、哪些能直接打开复制路径、哪些只是演示——3 秒内答得全即通过。
