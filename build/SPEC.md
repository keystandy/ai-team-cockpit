# AI 团队驾驶舱 · 浅色办公室风格设计规格书

> 实现依据：本文件是唯一视觉与交互基准。不沿用旧版深色、发光、监控台样式；未列出的装饰一律不做。

## 1. 设计目标与硬约束

- 气质参考 Notion / 飞书：安静、清楚、可编辑，像团队工作台，不像数据大屏。
- 用边框、底色和留白分层；**禁止阴影堆叠、发光、玻璃拟态、渐变、背景网格、噪点纹理**。
- 中性灰构成页面主体；主色只用于「可点击元素」和「当前选中／当前任务链路」，禁止大面积铺蓝。
- 卡片边框使用 `--border-strong: #E5E7EB` 一档；不得用深色粗框制造层级。
- 正文行高不得低于 1.5；不使用全大写英文标题，不使用倾斜正文。
- 所有状态必须同时有文字与图形标记，不能只靠颜色区分。
- 桌面优先，三栏完整展示；窄屏规则见第 12 节，不改变信息结构。

## 2. 色板

以下变量全站唯一取色来源；禁止新增近似色、透明发光色或临时十六进制值。

| 变量名 | 色值 | 用途 |
|---|---|---|
| `--bg-page` | `#F7F8FA` | 页面底色、栏间留白 |
| `--bg-card` | `#FFFFFF` | 顶栏、流程卡片、右栏卡片、输入区 |
| `--bg-overlay` | `#FFFFFF` | 下拉菜单、成员详情浮层、确认浮层；靠边框与页面区分 |
| `--bg-subtle` | `#F3F4F6` | 标签底、只读信息底、表格隔行、禁用控件底 |
| `--border-strong` | `#E5E7EB` | 卡片外框、输入框、浮层外框、主要分隔 |
| `--border-subtle` | `#F0F1F3` | 卡内分隔、列表行分隔、非当前连线 |
| `--text-primary` | `#1F2937` | 标题、正文、主要数字 |
| `--text-secondary` | `#6B7280` | 次要说明、时间、元信息 |
| `--text-placeholder` | `#9CA3AF` | 输入占位、空状态辅助文字 |
| `--primary` | `#2563EB` | 主按钮、可点链接、当前卡片描边、当前链路 |
| `--primary-hover` | `#1D4ED8` | 主按钮与链接的 hover、pressed |
| `--primary-soft` | `#EFF6FF` | 当前项选中底、输入框聚焦浅底；不可用作大区块背景 |
| `--status-online` | `#16A34A` | 在线状态点、完成勾选 |
| `--status-busy` | `#D97706` | 忙碌状态点、进行中标记 |
| `--status-offline` | `#9CA3AF` | 离线空心点、失效信息 |
| `--status-failed` | `#DC2626` | 失败叉号、错误文字、失败描边 |

补充用法：成功浅底用 `#F0FDF4`，警告浅底用 `#FFFBEB`，失败浅底用 `#FEF2F2`；仅用于状态标签或单行提示，不用于整卡铺色。浮层与卡片虽同为白色，浮层必须增加 `--border-strong` 实线外框。焦点环统一 `2px solid #2563EB`，外偏移 `2px`。

## 3. 字体与五级字号阶梯

字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。数字使用 `font-variant-numeric: tabular-nums`；不引入在线字体。

| 级别 | 字号／字重／行高 | 用途 |
|---|---|---|
| T1 页面标题 | `20px / 600 / 28px` | 顶栏品牌名、页面唯一主标题 |
| T2 卡片标题 | `16px / 600 / 24px` | 老板、小棒、员工姓名、右栏模块标题、弹层标题 |
| T3 正文 | `14px / 400 / 22px` | 任务正文、输入内容、按钮、事件描述、派活单正文 |
| T4 次要说明 | `12px / 400 / 20px` | 时间、角色、状态标签、占位、辅助说明 |
| T5 数字 | `24px / 600 / 32px` | 在线数、任务统计等独立大数字；行内统计数字仍用 T3 |

规则：只有上述 5 级。正文加粗可用 `600`，但不得创造第六级；图标尺寸不属于字号阶梯。长任务正文保持左对齐，标题不做居中排版。

## 4. 间距刻度

只允许 `0、4、8、12、16、20、24、32、40、48px`，对应变量 `--space-0` 至 `--space-9`。禁止出现 `2px、6px、10px、14px、18px` 等刻度外间距；边框宽度和焦点环不属于间距。

| 刻度 | 使用场景 |
|---|---|
| `4px` | 图标与紧邻文字、状态点与状态文字、标签内部纵向间距 |
| `8px` | 标签横向内边距、紧凑行间距、按钮图标与文字 |
| `12px` | 输入框与按钮内边距、卡内字段间距、列表项纵向内边距 |
| `16px` | 卡片常规内边距、按钮组间距、模块内段落间距 |
| `20px` | 卡片之间、右栏模块之间、主区节点纵向间距 |
| `24px` | 页面主区内边距、顶栏水平内边距、较大分组间距 |
| `32px` | 主区与右栏间距、老板与小棒的主要留白、页面区块间距 |
| `40px` | 小棒与员工组的主要留白、空状态上下留白 |
| `48px` | 页面大区块分隔；仅确有需要时使用，不为凑高度使用 |

布局尺寸另定：顶栏高 `64px`；页面最大宽 `1440px`，居中；主区最小宽 `640px`；右栏固定 `320px`；员工卡最小宽 `160px`。控件高度只用 `32px`（按钮、单行输入）和 `40px`（主派活按钮）；多行任务输入最小高 `96px`。这些属于结构尺寸，不得拿间距刻度拼接替代。

## 5. 圆角与边框

| 变量 | 值 | 用途 |
|---|---|---|
| `--radius-sm` | `4px` | 状态标签、小徽标、代码片、颜色标记 |
| `--radius-md` | `8px` | 按钮、输入框、员工卡、老板卡、小棒卡、右栏卡片、浮层 |
| `--radius-round` | `999px` | 状态点、头像、在线人数胶囊、进度轨道 |

除此之外不得使用圆角。普通卡片统一 `1px solid var(--border-strong)`；卡内分隔统一 `1px solid var(--border-subtle)`。默认无阴影；浮层也不加阴影。当前员工卡用 `1px solid var(--primary)` 加 `--primary-soft` 标题条，不用加粗至 2px。

## 6. 动效

| 场景 | 时长 | 缓动 |
|---|---|---|
| hover、颜色、描边、背景切换 | `120ms` | `cubic-bezier(0, 0, 0.2, 1)`（ease-out） |
| 选中、展开收起、连线状态切换 | `160ms` | 同上 |
| 浮层出现、内容替换 | `200ms` | 同上 |

- 允许过渡：`color、background-color、border-color、opacity`；展开与浮层可过渡 `transform`，仅用 `translateY(-4px) → translateY(0)`。
- 禁止过渡：`width、height、top、left、right、bottom、margin、padding、font-size、box-shadow`；不得用布局动画推动其他卡片。
- **禁止无限循环动画**，包括呼吸、闪烁、旋转、脉冲、光点飞行、虚线流动。忙碌仅用静态「◐ 忙碌」表达。
- 新事件插入只做一次 `160ms` 淡入，不自动反复滚动，不抢用户滚动位置。
- `prefers-reduced-motion: reduce` 时全部过渡与动画设为 `0ms`，功能与状态仍完整可见。

## 7. 状态语义

### 成员状态

| 状态 | 颜色 | 固定图形与文字 | 附加规则 |
|---|---|---|---|
| 在线 | `--status-online` | `● 在线`（实心圆） | 可接新任务；无任务时即为可派 |
| 忙碌 | `--status-busy` | `◐ 忙碌`（半实圆） | 显示当前子任务名；不自动再派 |
| 离线 | `--status-offline` | `○ 离线`（空心圆） | 姓名与元信息用次文字；禁止伪装成在线 |
| 失败 | `--status-failed` | `× 失败`（叉号） | 显示失败原因入口；成员恢复在线后仍需处理失败任务 |

标记采用文本符号或同形 SVG，视觉尺寸 `12px × 12px`，其后必须保留状态文字。员工头像旁放状态点，卡片元信息行再显示完整「图形 + 文字」。不得把四态改成四个仅靠颜色区分的圆点。

### 任务状态

| 状态 | 图形与文字 | 颜色规则 |
|---|---|---|
| 等待 | `○ 等待` | 中性灰；表示尚未被员工执行 |
| 进行 | `▶ 进行` | 当前链路用主色，执行成员显示 `◐ 忙碌` |
| 完成 | `✓ 完成` | 使用在线绿；任务终态，不再显示为当前链路 |
| 失败 | `× 失败` | 使用失败红；保留错误详情和重试入口 |

## 8. 页面结构与视觉层级

1. **顶栏**：白底、底部 `--border-strong`；左为品牌与 T1 标题，右为「在线 n/4」胶囊、同步时间（T4）、刷新按钮。刷新按钮用主色文字或描边，不做整块蓝色顶栏。
2. **主区**：标题「任务流程」+ 当前任务摘要；下方依次是老板输入卡、小棒协调卡、四员工卡组。节点纵向排列，员工卡可一行四列或两列换行；顺序不可颠倒。
3. **右栏**：三段白底卡片，顺序固定为「实时事件流」「成员详情」「派活单」。右栏不是深色侧栏，不贴满屏高蓝色背景。
4. 所有主要模块以 `--bg-card`、`--border-strong`、`--radius-md` 组成；页面底色只从栏间与卡间留白露出。

## 9. 流程图视觉规定

- 信息流必须保留：**老板（任务输入窗口）→ 小棒 → 四名员工**。箭头方向单一、明确，不增加旁路装饰线。
- 老板卡内含任务多行输入、清空按钮和主按钮「派发任务」；占位为「描述目标、交付物和约束…」。空内容时主按钮禁用，禁用用灰底灰字，不用降低全页透明度。
- 小棒卡为协调节点：显示「小棒」「拆解与分派」及当前汇总状态；不做机器人发光插画。
- 员工卡显示头像、姓名、角色、成员状态、当前子任务；无任务写「暂无任务」，失败写一行原因摘要。
- 连线为 `1px` 实线，默认 `--border-subtle`；拐点圆角可用 `--radius-sm`。箭头为简洁小三角，线宽不随状态变粗。
- 当前链路（老板 → 小棒 → 当前执行员工）改为 `--primary`，目标员工卡描边也为主色；未参与链路保持浅灰。
- 完成链路恢复浅灰，在完成员工卡上显示 `✓ 完成`；失败链路仅目标员工卡及最后一段连线用 `--status-failed`，上游不整片染红。
- 不绘制飞行光点、流动虚线、粒子、扫描线；不用动画表达进度。进度由「当前链路主色高亮 + 状态文字」表达。
- 连线不得压住文字与卡片，交叉时优先正交绕行；员工卡同层等宽、等高、对齐。

## 10. 任务状态机与界面响应

| 场景／状态 | 谁的卡片高亮 | 右栏显示 | 连线样式 | 用户能做什么 |
|---|---|---|---|---|
| 等待 | 老板卡为当前项（主色描边）；小棒与员工灰态 | 事件流新增「任务已创建」；成员详情默认选中小棒；派活单显示待拆解内容与「确认派发」 | 老板 → 小棒主色；其余浅灰实线 | 编辑任务、取消等待、确认派发、选择成员 |
| 进行 | 小棒与当前执行员工为当前项；其他员工不高亮 | 事件流追加开始／进度事件；成员详情显示当前员工、子任务、开始时间；派活单显示子任务进度 | 老板 → 小棒 → 执行员工主色；其他浅灰 | 查看详情、切换成员、暂停或取消未开始子任务；不可重复派发同一任务 |
| 完成 | 无当前高亮；完成员工卡显示绿色 `✓ 完成` | 事件流新增完成时间与交付摘要；成员详情显示交付物；派活单显示全部完成及结果 | 全部恢复浅灰实线，不保留蓝色链路 | 查看交付摘要、复制结果、创建新任务、归档 |
| 失败 | 失败员工卡红色描边；小棒显示失败汇总，不铺红底 | 事件流新增失败原因；成员详情显示错误详情；派活单定位失败子任务并显示「重试」「改派」 | 小棒 → 失败员工最后一段红色实线；其余浅灰 | 查看原因、重试、改派在线成员、修改任务后重试、取消任务 |
| 成员离线时派活 | 离线成员卡不高亮，显示 `○ 离线` | 成员详情标注「离线，不能直接接收」；派活单中该成员不可选，并给出替代在线成员 | 不绘制指向离线成员的当前主色链路 | 改派在线成员；或加入等待队列并明确标注「待成员上线」，不得假装执行中 |
| 子任务失败退回 | 小棒成为当前项；失败员工保留红色失败标记 | 事件流记录「已退回拆解」；派活单把该子任务置为等待并保留失败历史；成员详情显示退回原因 | 失败员工 → 小棒仅显示一次主色回退箭头；稳定后老板 → 小棒主色 | 修改子任务、重试原成员（须在线）、改派、取消；退回不抹除失败记录 |

补充约束：同一时刻最多一条当前主色执行链路；并行子任务时，主区只高亮用户当前选中的员工链路，派活单列出全部进行项。状态切换以派活单和事件流为准，不只改变卡片颜色。取消、改派需二次确认；普通查看与选择不弹窗。

## 11. 控件与交互细节

- **主按钮**：`--primary` 底、白字、`--radius-md`；hover 用 `--primary-hover`。每个视图最多一个主按钮。
- **次按钮**：白底、`--border-strong` 描边、主文字；hover 用 `--bg-subtle`，不自动变蓝底。
- **文字按钮／链接**：主色文字，hover 用 `--primary-hover`；危险操作文字用失败红，仅在对应操作中出现。
- **输入框**：白底、`--border-strong`；hover 不改变底色，focus 改主色描边并显示焦点环。错误时红描边并在下方给出具体错误文字。
- **选中态**：列表当前项使用 `--primary-soft` 底 + 左侧 `4px` 主色标记；非当前 hover 仅用 `--bg-subtle`。
- **刷新**：点击后立即更新同步时间；单次忙碌可显示按钮内静态「同步中」，禁止旋转图标。失败时显示「同步失败，请重试」。
- **事件流**：时间在前、事件在后；新事件在顶部插入。用户已向上滚动时不强制跳顶，显示「有新事件」文字按钮。
- **成员详情**：点员工卡切换，选中卡描边主色；离线成员仍可查看历史与待接任务。
- **派活单**：按子任务列成员、状态、操作；操作按钮不用图标单独表意，必须有文字或可访问名称。
- **空状态**：使用 T3 标题 + T4 说明，如「还没有事件」「选择成员查看详情」，不使用大幅插画。

## 12. 响应式与可访问性

- `≥ 1200px`：主区 + `320px` 右栏并排，栏间距 `32px`。
- `768–1199px`：右栏移至主区下方，员工卡两列；顶栏允许换行，间距仍只用既定刻度。
- `< 768px`：单栏，老板、小棒、员工、右栏依次排列；员工卡一列；连线保持纵向正交，不横向挤压文字。
- 页面横向内边距桌面 `24px`、窄屏 `16px`；不得引入刻度外值。
- 键盘可到达全部按钮、输入框、员工卡和事件；焦点顺序与视觉顺序一致，焦点环不可移除。
- 正文与背景对比度至少 4.5:1；状态标记带文字，图标按钮提供 `aria-label`，状态更新区域使用非打断式 `aria-live="polite"`。
- 触控点击区域最小 `40px × 40px`；不得只靠 hover 展示必要操作。

## 13. 实现验收清单

- 页面、顶栏、主区、右栏全部为浅色，无旧版深色监控台残留。
- 全站只出现规定色板、5 级字号、3 种圆角与既定间距；没有随意新增视觉Token。
- 无发光、无玻璃拟态、无渐变、无阴影堆叠、无无限循环动画。
- 主色只用于可点与当前；页面不存在大面积蓝底。
- 老板 → 小棒 → 四名员工结构清晰，连线默认浅灰，当前链路主色高亮。
- 在线／忙碌／离线／失败均有不同图形与文字；任务四态均有明确反馈。
- 成员离线不能伪装执行；子任务失败可退回、重试、改派，历史不丢失。
- 正文行高 ≥ 1.5，所有过渡在 120–200ms 且 ease-out；减少动态效果设置生效。
